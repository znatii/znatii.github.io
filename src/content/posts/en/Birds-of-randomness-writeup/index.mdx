_You think you found your soulmate, but you lost the train ticket that your love gave you to meet again. The only thing that you remember is the coordinates of the departing station and your love disappearing into the steam of the train._

### Challenge Analysis
This challenge uses _Elliptic Curves_ to calculate the coordinates of the train stations where we'll look for our "love". First of all, the curve and generator are set up with the following parameters, none of which seem to have an odd or vulnerable length:

As you can see, the seed is divided by 30268, the result is divided by 30306 and the next one 30322, and we keep the remainder of each operation (x,y,z).
The _goToNextStation_ function is the one that computes the private key and the next point (public key). For it to be considered a valid key, the seed (x,y,z) will be rotated until all three are primes. We can see it's using a 5-digit PRNG (Wichmann-Hill algorithm). Therefore, these numbers could become predictable and $d$ could turn out to be factorable (product of 3 5-digit primes).

We are given the first coordinates and we have to predict the next ones, we have 6 tries.

### Attack 
As we observed, $d$ is not excessively large (factor of 3 5-digit primes), $d = x*y*z$ where $x,y,z <30323$, so in the worst-case scenario $d=30323^3=2.7*10^{13}$, which leaves us with $\\sqrt{d} \\approx 5.2 \\times 10^6$, quite manageable computationally.
We also know the upper bound $d<30269 \times 30307 \times 30323$, which is an important piece of info to solve the discrete algorithm problem.
The path to take seems to be the following:
1. Calculate $d1$ by solving the ECDLP (Discrete Logarithm Problem) using the Baby-Step Giant-Step attack.
2. Factor $d1$ into its three prime factors.
3. Predict the next PRNG state.
4. We've got 6 chances because even if we know the 3 factors, we don't know the order they were used in, giving us 6 possible permutations.

### Writeup

We're going to follow the steps we discussed before. First, let's define the curve.
```python
import math  
from itertools import permutations  
from ecdsa import ellipticcurve as ecc  
from Crypto.Util.number import isPrime  
  
# Elliptic curve

E = ecc.CurveFp(p, 2, 3)  
G = ecc.Point(E, Gx, Gy, ec_order)
```
To find the factors of $d$ we'll need the list of primes smaller than **30323** because that's the largest modulus, so none of the factors will be larger than that.
```python
def primos(n):  
    is_prime = [True] * (n + 1)  
    is_prime[0] = is_prime[1] = False  
    for i in range(2, int(math.sqrt(n)) + 1):  
        if is_prime[i]:  
            for j in range(i * i, n + 1, i):  
                is_prime[j] = False  
    return [i for i in range(2, n + 1) if is_prime[i]]
    
primes_list = primos(30323)
```
We'll also need the PRNG code to simulate the state and predict the coordinates, so we'll just replicate the exact logic from the challenge.
```python
def rotate(seed):
    x, y, z = seed
    x = (171 * x) % 30269
    y = (172 * y) % 30307
    z = (170 * z) % 30323
    return (x, y, z)

def next_station(state):
    while True:
        state = rotate(state)
        x, y, z = state
        if isPrime(x) and isPrime(y) and isPrime(z):
            d = x * y * z
            P = d * G
            return (int(P.x()), int(P.y()))
```
Now, we need the code for the attack we're going to use, Baby-Step Giant-Step:
1. **Baby Steps**: Precalculate and store $j\times G$ for $j = 1...m$
2. **Giant Steps**: Calculate $P - i\times (m\times G)$ for $i = 1...m$
3. **Find match**: When we find that $j\times G = P - i\times (m\times G)$, then $d = j + i\times m$

```python
# Baby-step giant-step algorithm to solve the discrete logarithm  
def BSGS(P, G, M):  # Point, Curve, largest possible d
    m = int(math.isqrt(M)) + 1  
    print(f"[+] Using m = {m}")  
  
    # Precalculate m*G  
    mG = m * G  
    print("[+] Computed mG")  
  
    # Baby steps: store points j*G for j=1..m  
    baby = {}  
    current = G  
    for j in range(1, m + 1):  
        if j % 100000 == 0:  
            print(f"[+] Baby step {j}/{m}")  
        x = int(current.x())  
        y = int(current.y())  
        baby[(x, y)] = j  
        current = current + G  
    print("[+] Baby steps completed")  
  
    # Giant steps: look for P - i*m*G in baby steps  
    current = P  
    minus_mG = -mG  
    for i in range(0, m + 1):  
        if i % 100000 == 0:  
            print(f"[+] Giant step {i}/{m}")  
        if current is None:  
            d = i * m  
            if 1 <= d <= M:  
                return d  
        else:  
            x = int(current.x())  
            y = int(current.y())  
            if (x, y) in baby:  
                j = baby[(x, y)]  
                d = i * m + j  
                if 1 <= d <= M:  
                    return d  
        current = current + minus_mG  
    return None
```

We create the point $P1$ to calculate $d1$ such that $P1=d1*G$ using the attack above, and finally, we factor $d1$ into the three prime numbers.
```python
# Calculate d1 for (first station)

factors = []

for p in primes_list:
    while temp % p == 0:
        factors.append(p)
        temp //= p
    if temp == 1:

```
Lastly, with the three primes, we'll be able to predict the next point, which will be the solution, keeping in mind that there are 6 possible combinations (permutation of 3) and we just try which one of the 6 combinations solves the challenge.
```python
# Generate permutations of the factors
candidates = list(permutations(factors))
next_points = []
for cand in candidates:
    next_point = next_station(cand)
    next_points.append(next_point)
```
